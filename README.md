# 本地符号执行与路径约束求解服务

一个基于 Spring Boot 的本地服务，对由**整数变量、赋值、条件分支、有界循环和断言**构成的小型程序做
符号执行：枚举可达路径、收集路径约束、用整数线性算术求解器给出可满足赋值，并区分断言成功/失败路径。
支持多任务并发提交、任务级隔离、资源上限、取消与超时，以及基于检查点的中断恢复。

## 构建与运行

```bash
mvn spring-boot:run            # 启动服务（默认端口 8080）
mvn test                       # 运行全部 46 个自动化测试
```

数据目录默认 `./data`，可通过 `--analysis.data-dir=/path` 修改。

## 支持的语言子集与语义

程序是一个 JSON 对象，包含 `variables` 与 `statements`：

```json
{
  "variables": [
    {"name": "x", "input": true},
    {"name": "i"}
  ],
  "statements": [ ... ]
}
```

- **变量**：只有 64 位有符号整数一种类型。`"input": true` 的变量是符号输入（初值任意），
  其余变量初值为 `0`。
- **表达式**
  - 常量 `{"kind":"const","value":1}`、变量 `{"kind":"var","name":"x"}`
  - 一元：`neg`（一元负号，作用于整数）、`not`（逻辑非，作用于布尔）
  - 二元整数运算：`add`、`sub`、`mul`（仅支持**线性**乘法：至少一侧是常量，
    如 `2*x`；`x*y` 这类非线性乘法会被拒绝）
  - 比较运算（产生布尔）：`eq`、`ne`、`lt`、`le`、`gt`、`ge`
  - 布尔连接：`and`、`or`（仅作用于布尔表达式；通过取反实现分支否定）
  - `div` / `mod` 不在支持的线性子集中，提交时会被明确拒绝。
- **语句**
  - 赋值 `{"kind":"assign","line":1,"target":"i","expression":{...}}`
  - 条件 `{"kind":"if","condition":<bool>,"then":[...],"else":[...]}`
    （`else` 可省略）
  - 循环 `{"kind":"loop","condition":<bool>,"maxIterations":N,"body":[...]}`
  - 断言 `{"kind":"assert","line":4,"condition":<bool>}`
- **循环语义**：循环头携带**声明上限** `maxIterations`（非负整数，缺失即拒绝）。
  符号执行按该上限展开：达到上限后强制走退出边，绝不无限执行。
- **断言语义**：同一条断言会分别探索成功路径与失败路径。
  - 失败路径（约束取反可满足）记录 `ASSERT_VIOLATED`，该路径在断言处终止；
  - 成功路径（原条件可满足）记录 `ASSERT_PASSED` 并继续执行后续语句；
  - 走到程序末尾的路径记录 `PATH_COMPLETED`。

## 静态校验与错误定位

解析后做静态校验，错误会以 HTTP 400 返回，并带结构化的位置信息：

- 引用未声明变量、赋值给未声明变量；
- 类型不一致（对布尔做算术、对整数做逻辑运算、非布尔用作 `if/loop/assert` 条件、
  把布尔表达式赋给整数变量）；
- 循环缺少 `maxIterations` 或为负；
- 非线性乘法、`div/mod`、未知算子、JSON 结构错误等。

位置采用 JSONPath 风格并尽量附带来源行号，例如
`"$.statements[0].condition (line 5)"`、`"$.variables[1].name"`。

## 约束求解

- 约束形式为整数线性算术的合取：`a·x ≤ b`。
  `lt` 对整数加强 1（`e < 0` ⇒ `e + 1 ≤ 0`），`eq` 拆成一对不等式，
  `ne` 用确定性两路分裂（`e ≤ -1` 或 `-e ≤ -1`）。
- 判定过程：加入标准整数可行性完备边界框（`n!·M^n`，n 为变量数、M 为最大系数/右端项），
  预计算 Fourier–Motzkin 消元层级，再按逆消元序用精确的逐变量上下界做确定性回溯。
- **路径条件无解立即剪枝**：每个分支后继入队前先做可满足性判断，不可满足的后继不进入前沿。
- **常量折叠与去重**：当条件在当前符号环境下退化为具体常量时直接判定真假
  （不产生约束、不调用求解器），与已有路径条件重复的约束也不再累积。因此纯具体的
  有界循环按 O(循环上限) 执行，路径条件不会随迭代无意义膨胀。
- 有解时返回一个具体整数模型；未出现在约束中的输入变量按确定性默认值 `0` 补全。
- 求解器本身是确定性的：同一约束合取永远给出相同结论与相同模型
  （候选值固定按 `0, 1, -1, 2, -2, …` 顺序尝试）。

## 确定性与随机种子

- 默认 `seed = 0` 时，探索顺序固定为广度优先、每个分支 TRUE 备选先于 FALSE 备选。
- `seed` 非 0 时，每个分支的可行后继用由 `(seed, 节点, 深度)` 派生的伪随机数确定性洗牌；
  洗牌不依赖跨状态携带的随机流，因此**重启恢复后仍会做出完全相同的选择**。
- 相同程序 + 相同种子，无论经过多少个调度量子、是否中途重启，路径编号、约束、模型与
  最终变量值都逐次一致。路径编号 `pathId` 从 0 开始、连续且不重复。

## REST API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/tasks` | 提交分析任务，返回 `202 {"taskId": ...}` |
| GET | `/api/tasks` | 列出全部任务 |
| GET | `/api/tasks/{id}` | 查询单个任务状态与（完成后的）结果 |
| POST | `/api/tasks/{id}/cancel` | 请求取消 |

提交请求体：

```json
{
  "program": { ... 上面的程序 JSON ... },
  "seed": 0,
  "timeoutMs": 30000,
  "maxStates": 1000000,
  "maxPaths": 10000
}
```

限制字段均可省略，缺省值由服务端配置给出。任务状态：
`QUEUED / RUNNING / COMPLETED / CANCELLED / TIMEOUT / LIMIT_EXCEEDED / FAILED`。

结果中的每条 finding：

```json
{
  "pathId": 0,
  "kind": "ASSERT_VIOLATED",
  "line": 4,
  "pathCondition": [ {"expression": {...}, "relation": "GE"} ],
  "model": {"x": -1},
  "finalValues": {"x": -1, "i": 0}
}
```

错误响应形如 `{"error": "loop bound missing: ...", "location": "$.statements[0] (line 9)"}`。

## 并发隔离、资源上限、取消与超时

- 每个任务拥有**独立的**执行器、前沿、路径条件、求解器与时钟；工作线程数受
  `analysis.workers` 限制。
- 调度采用**量子化轮转**：一个任务一次只执行 `analysis.quantum-states` 个状态，
  之后保存检查点并重新排到队尾，因此慢任务不会饿死其他任务。
- 每个任务有独立的超时（墙钟截止时间）、状态数上限与路径数上限；
  超限分别给出 `TIMEOUT` / `LIMIT_EXCEEDED`。
- 取消是协作式的，每个状态展开前检查取消标志与截止时间。
- **超时或取消不会留下部分结果**：此时不挂载任何 result，并删除中间检查点。

## 检查点与恢复

- 任务记录在受理与每次生命周期变更时**原子写入**（写临时文件后 rename）
  `data/tasks/<taskId>/task.json`。
- 每个运行量子结束后，把完整探索快照（前沿 + 已提交 findings + 计数器 + 终结状态）原子写入
  `checkpoint.json`。
- 进程重启后自动从最近快照恢复：已终结任务可继续查询，未终结任务重新入队，
  **不重复报告已发现路径，也不漏报尚未探索的路径**。
- 崩溃残留的 `.tmp` 文件在启动时清理，避免半截文件被读取。

## 配置项（application.properties）

| 键 | 默认值 | 含义 |
| --- | --- | --- |
| `analysis.workers` | 2 | 执行量子的工作线程数 |
| `analysis.max-active-tasks` | 64 | 在队/在跑任务上限，超过则拒绝（429） |
| `analysis.quantum-states` | 256 | 每次调度处理的前沿状态数 |
| `analysis.data-dir` | data | 任务记录与检查点目录 |
| `analysis.default-timeout-ms` | 30000 | 默认任务超时 |
| `analysis.default-max-states` | 1000000 | 默认状态数上限 |
| `analysis.default-max-paths` | 10000 | 默认路径数上限 |

## 测试覆盖

- 解析与错误定位（JSONPath + 行号）；
- 静态校验：未定义变量、类型不一致、缺失循环边界、非线性、`div/mod`；
- 求解器：不可满足剪枝、整数无解（如有理可行但整数不可行的 `2x=1`）、
  NE 分裂、严格不等式、负系数、确定性模型；
- 符号执行：分支取反、循环按上限展开、断言成功/失败、不可满足分支剪枝、
  最终变量值、确定性（不同量子大小结果一致）、检查点反复恢复不重不漏；
- 任务层：并发公平（慢任务不阻塞快任务）、取消无部分结果、超时无部分结果、
  容量拒绝、重启恢复、同种子同报告；
- REST API：提交-轮询-结果、错误位置、404、取消。
